Git 基础与核心操作 — 入门教程

写给 Git 新手的图文教程。读完能上手，再读能懂原理。

一、Git 是什么？为什么用？

一句话解释

Git 是一个分布式版本控制系统——通俗的讲就是”代码的时光机 + 协作记事本”。

它干两件事：

  1. 记录你文件的每一次改动（谁改的、什么时候改的、改了啥），随时能回滚

  2. 让多人同时改同一份代码而不打架

为什么不用”复制文件夹”？

老办法是 项目_v1 → 项目_v2 → 项目_最终版 → 项目_真的最终版。问题是：

  • 不知道哪一版是哪个

  • 多人改同一文件时，谁覆盖谁全靠吼

  • 想看历史只能靠记忆

Git 把这些全自动化了。

Git vs GitHub：不是一回事

  • Git：装在你电脑上的版本控制软件（工具）

  • GitHub / Gitee / GitLab：放 Git 仓库的远程服务器（平台）

你可以在完全不用 GitHub 的情况下用 Git；也可以把 Git 仓库放在自己的服务器上。

二、核心概念：三大工作区

这是 Git 最核心的概念，搞懂这一节后面的命令全是顺水推舟。

三个区域

区域 英文 比喻 存放在哪
工作区 Working Directory 你的办公桌 你的项目文件夹
暂存区 Staging Area / Index 待提交清单 .git/index 文件
仓库 Repository 公司档案室 .git/ 目录

流转图

文件的三个状态

对应上面的三个区域，每个文件在 Git 眼里有三种状态：

状态 英文 含义
已修改 Modified 工作区里改了，但还没 git add
已暂存 Staged 改了并且 git add 了，等着提交
已提交 Committed 已经在仓库里，安全保存
任何时候文件只可能处于这三种状态之一。git status 就是告诉你哪些文件处于哪种状态。

第四步：第一次提交

看到 [main (root-commit) abc1234] 就说明提交成功了。abc1234 是这次提交的哈希值（前 7 位），相当于这次提交的”身份证号”。

四、基础命令详解

git init — 初始化仓库

把当前目录变成 Git 仓库，生成 .git/ 目录。

git clone <url> — 克隆远程仓库

把远程仓库完整下载到本地，包括所有历史记录。

git add — 添加到暂存区

小坑：git add . 不会添加被 .gitignore 忽略的文件。

git commit — 提交到仓库

写好 commit message 是基本素养：

  • 第一行 ≤ 50 字，概括这次干了啥

  • 空一行

  • 详细说明（可选）

  • 祈使句：”add feature” 而不是 “added feature” 或 “adds feature”

五、远程协作

远程仓库 = 放在服务器上的 Git 仓库（GitHub / Gitee / GitLab / 自己服务器）。

git remote — 管理远程仓库

origin 是远程仓库的默认名字（约定俗成），可以改成别的，但一般没人改。

git push — 推送到远程

**第一次推送要加 -u**：

-u 关联之后，以后直接 git push 就够了。

git pull — 拉取远程更新

git pull 其实是两步：git fetch + git merge。

git fetch — 仅下载不合并

什么时候用 fetch 而不是 pull？

  • 想先看看远程有什么新东西再决定合不合并

  • 多远程协作时（origin + upstream 都有更新）

七、冲突解决

什么是冲突

两个人改了同一文件的同一行——Git 没法判断该听谁的，于是停下来让你拍板。

冲突文件长这样

打开冲突文件，会看到冲突标记：

  • <<<<<<< HEAD 到 ======= 之间：当前分支（HEAD）的内容

  • ======= 到 >>>>>>> feature/login 之间：要合并进来的分支的内容

[图片说明：冲突标记示意图，标注三个区域分别代表什么]

解决步骤

  1. 打开冲突文件，看清楚两边都写了啥

  2. 手动决定保留什么（保留一边 / 两边都留 / 两边都改 / 都不留）

  3. 删除所有冲突标记（<<<<<<<、=======、>>>>>>>）

  4. 保存文件

实用技巧

| 命令 | 作用 |

|—|—|

| git status | 查看哪些文件冲突 |

| git diff | 看具体冲突内容 |

| git merge --abort | 放弃合并，回到合并前状态 |

| git checkout --ours file.txt | 冲突文件保留当前分支版本 |

| git checkout --theirs file.txt | 冲突文件保留对方版本 |

| git rerere | 记住冲突解决方案，下次自动套用 |

预防冲突的几个习惯

  • **频繁 git pull**：开始干活前先拉最新

  • 小步提交：一次只改一件事，减少冲突面

  • 明确分工：团队约定好谁改哪个文件

  • **用 .gitignore**：避免不小心提交二进制文件、依赖、密码

九、救命命令（出错了别慌）

| 场景 | 命令 |

|—|—|

| 撤销 git add（文件还在） | git restore --staged <file> |

| 撤销工作区修改（危险，不可恢复） | git restore <file> |

| 修改上一次 commit message | git commit --amend |

| 改上一次 commit 内容（加新文件） | git add . && git commit --amend |

| 撤销上一次 commit（保留改动） | git reset --soft HEAD~1 |

| 撤销上一次 commit（不保留改动，危险） | git reset --hard HEAD~1 |

| 放弃 merge，回到 merge 之前 | git merge --abort |

| 找回误删的分支 | git reflog + git checkout <hash> |

| 找回误删的 commit | git reflog + git reset --hard <hash> |

git reflog — 救命神器

reflog 记录你所有的 HEAD 移动历史。就算你把分支删了、把 commit 丢了，reflog 里都有记录。

找到想回去的哈希，git reset --hard <hash> 就能回去。

十、常见问题 FAQ

Q: .git 目录能不能删？

A: 能删，但删了之后这个目录就不再是 Git 仓库了，所有历史都没了。别手贱。

Q: 提交了不该提交的文件怎么办？

Q: main 还是 master？

A: 2020 年后 GitHub 默认分支改名 main，老项目可能还是 master。两个都行，别纠结。

Q: Git 和 SVN 啥区别？

A: SVN 是中央式（一个中心服务器），Git 是分布式（人人都有完整历史）。Git 离线能干活，SVN 不行。
